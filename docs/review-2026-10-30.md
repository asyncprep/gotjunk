# Review — Oct 30, 2026

Full review of the backend, the admin app and the crew app, against the spec and the client's
answers. Two independent reviewers plus automated checks.

## Fixed (backend and admin, migration 1000)

| # | Problem | Fix |
| --- | --- | --- |
| 1 | A truck couldn't run two shifts a day (contradicted client answer H2) | Per-day truck/phone uniqueness removed; a person can do a second shift once their first is submitted; admin no longer hides used trucks/phones |
| 2 | An admin could make themselves senior ops or give themselves configuration rights | Only senior ops grants senior ops or config rights; nobody can change their own access |
| 3 | Anyone with the public key could read any shift's readiness checks | Database functions can no longer be called anonymously |
| 4 | A tip could go to nobody (crew times wrong) without any warning | New check `tip_unassigned` (blocks acceptance); dispatch can now correct crew joined/left times |
| 5 | A photo row could point to another shift's file, or to a file never uploaded | Photo files must be in their shift's folder; acceptance checks the file is really in storage (`photo_not_uploaded`) |
| 6 | A shift that won't run could never be closed | Dispatch can cancel an open shift, with a reason |
| 7 | Crew could change fields they shouldn't (who locked, reconciliation status…), or delete a cash count | Crew may only change an explicit list of fields; counted cash can't be deleted by crew |
| 8 | Correcting a rank the same day failed | Setting a rank replaces the rows it supersedes |
| 9 | Recording a cash count when the crew never created the cash record silently saved nothing | Admin saves with an upsert; the cash form is shown even without the crew's record |
| 10 | A new disposal rate starting the day the old one ended failed; credits could get a minimum | `add_site_rate()` closes the old rate the day before; credits can't have a minimum (constraint) |
| 11 | Some database errors appeared in English in the French admin | Missing translations added; duplicate errors explained |
| — | Docs out of step with the client's answers | `decisions.md`, `project.md`, `client-questions.md` and the Projet items updated |

Tests: 49 database tests (13 new for these fixes), admin type check and build.

## For the crew app (apps/mobile) — not changed here, owned by the crew-app session

Most severe first.

1. **Unexpected sign-out erases unsent work.** `lib/data/database.dart` wipes the database and the
   photo folder on every `signedOut` event, including one caused by a failed token refresh
   (`signOutReason: sessionExpired`), which the iOS background upload engine can trigger by
   refreshing the token in parallel. Wipe only on the app's own explicit sign-out after the
   upload queue is empty; don't refresh tokens from the background engine.
2. **Send the phone's own times.** The server now keeps what the phone sends:
   `start_time` (and `truck_phone_confirmed_at`) when starting the shift, and `completed_at`
   when a job becomes completed. Today the phone sends neither, so a shift worked offline gets
   its start time at upload, which can make `finish_time < start_time` (constraint 23514) and
   tips go to the wrong people.
3. **Photo paths after an iOS update.** `field_repo.dart` stores the absolute local path; iOS
   changes the app folder on update/reinstall. Store the file name and rebuild the path.
4. **Two shifts a day.** `repo.currentShift` takes `ORDER BY shift_date DESC LIMIT 1`; with two
   shifts on one date it can show the submitted morning shift. Order active shifts first.
5. **Refused changes drop data.** One refusal (e.g. duplicate ticket number) drops a whole visit
   with its weigh-ins and photo; a PATCH matching 0 rows looks like success. Validate on the
   phone first and keep refused changes so the crew can fix them.
6. **Disposal "Done" after submit** sends an update the server always refuses (red card every time).
7. **Untranslated refusals**: `no_rate`, `crew_double_booked`, `photo_entity_missing`,
   `invalid_transition`, `reason_required`, constraint/unique messages. New codes from this
   review: `tip_unassigned`, `photo_not_uploaded`, `photo_shift_mismatch` ("photo file must be in
   its shift's folder"), `not_allowed: crew cannot change …`.
8. Smaller: photo uploader retries refusals forever in the foreground; "not crew" flashes before
   the first sync; today's date fixed when the screen is built; no `onError` on the auth listener;
   Codemagic builds use the development PowerSync instance (fine for the pilot if intended).

Shared phone: the app assumes one personal login per crew member ("ma part des pourboires",
sign-out wipe, sync filtered by employee). Waiting on the login-model decision.

## Still open (not bugs)

- **Public sign-ups**: confirm they are disabled on `gotjunk-ca` (Authentication → Sign In /
  Providers), so invitations are the only way in.
- **invite-user** uses the legacy anon/service keys; if those are disabled in favour of the new
  key system, it must be updated. Untested in production so far.
- The `powersync` publication replicates all columns of `app_user`/`employee` (email,
  Ceridian ID) to the US sync service even though the sync rules don't send them to phones.
